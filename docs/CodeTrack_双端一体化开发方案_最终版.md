# CodeTrack 双端一体化开发方案（最终可开发版）

> 项目定位：CodeTrack 是一个统一的教学与学习平台，教师端和学生端不是两个独立系统，而是同一套课程、任务、知识、评测、AI 和学习数据上的两个角色端。  
> 文档目的：明确教师端最终页面模块、页面控件、学生端联动关系、开发边界与开发顺序，作为后续多人开发的统一依据。

---

# 一、产品整体闭环

```text
教师创建课程教学内容
→ 教师配置资料、任务、评分和评测规则
→ 教师发布任务到班级
→ 学生在学生端接收并完成任务
→ 系统完成判题、测试和 AI 诊断
→ 学生查看提示、反馈和学习画像
→ 教师查看任务进度、班级学情和个体诊断
→ 教师审核 AI、发送反馈、调整教学任务
→ 学生完成补救学习或下一阶段任务
→ 系统继续沉淀学习证据
```

平台最终形成：

```text
教学准备
→ 学生学习
→ 自动评测
→ 学情诊断
→ 教师干预
→ 教学改进
```

# 二、双端统一原则

## 2.1 一个项目，两种角色端

| 内容 | 教师端 | 学生端 |
|---|---|---|
| 课程 | 配置课程教学内容 | 查看自己加入的课程 |
| 班级 | 查看负责班级和学生 | 查看自己所在班级 |
| 任务 | 创建、配置、发布和调整 | 接收、完成和提交 |
| 资料 | 上传、分类、启用和共享 | 查看、收藏和用于自主学习 |
| 评测 | 配置标准、测试用例和开放规则 | 查看允许公开的结果 |
| AI | 审核诊断、生成教学建议 | 获取诊断、提示、导师问答 |
| 学情 | 查看班级与学生学情 | 查看自己的学习画像 |
| 反馈 | 编写和发布教师反馈 | 接收和查看反馈 |
| 教学改进 | 调整任务和教学策略 | 接收新的学习任务与资源 |

## 2.2 必须共用的能力

教师端和学生端必须共用：

- [ ] 同一套用户与角色体系
- [ ] 同一套课程和班级数据
- [ ] 同一套任务和任务发布数据
- [ ] 同一套题目和测试用例
- [ ] 同一套提交、判题和沙箱执行结果
- [ ] 同一套 AI 模型网关
- [ ] 同一套课程知识库
- [ ] 同一套学习事件和能力证据
- [ ] 同一套学习画像计算结果
- [ ] 同一套通知和审计记录

不得为教师端和学生端分别复制一套课程、任务或提交数据。

## 2.3 两端职责边界

### 教师端负责

- 教学内容生产
- 教学规则配置
- 任务发布与管理
- 学习过程监控
- AI 结果审核
- 人工反馈和教学干预
- 教学效果分析

### 学生端负责

- 接收任务
- 完成题目与编程任务
- 查看公开测试结果
- 使用分层提示
- 接收 AI 与教师反馈
- 自主学习
- 查看个人学习画像

### 管理员端后续负责

以下功能不放入教师端第一版：

- 创建和删除教师账号
- 创建行政班
- 修改学生专业和行政班
- 分配教师授课关系
- 删除学生账号
- 管理全平台系统配置

# 三、双端页面对应关系

| 教师端页面 | 影响的学生端页面 | 联动内容 |
|---|---|---|
| 课程与班级 | 学习首页、班级任务 | 决定学生可见课程和教学班 |
| 课程大纲 | 学习首页、自主学习 | 决定章节和知识点结构 |
| 知识资源 | 自主学习、AI 导师、收藏夹 | 提供课程资料和 AI 引用来源 |
| 任务管理 | 班级任务 | 决定学生可见任务内容 |
| 任务发布 | 班级任务、通知 | 决定发布时间、截止时间和提交规则 |
| 编程任务配置 | 编程工作台 | 决定初始代码、测试、提示和限制 |
| 客观题配置 | 题目作答页 | 决定题目、答案、解析和作答规则 |
| 作业监控 | 无直接编辑 | 读取学生提交、成绩和任务状态 |
| 教师反馈 | 任务详情、通知 | 向学生展示教师评语 |
| AI 审核 | AI 诊断、任务工作台 | 标记诊断是否经过教师确认 |
| 学生学情 | 学习画像 | 读取同一套画像数据，不另算一套 |
| 教学改进 | 班级任务、学习推荐 | 下发调整后的任务、资料和补救任务 |

# 四、教师端总体导航

教师端第一版导航建议固定为：

```text
1. 教学首页
2. 课程教学
3. 资料中心
4. 任务中心
5. 任务监控
6. 学情诊断
7. AI 审核
8. 教学改进
```

顶部全局区域始终显示：

- 当前学期
- 当前课程
- 当前班级
- 消息通知
- 教师个人菜单

切换课程或班级后，当前页面数据必须同步刷新。

# 五、页面模块一：教学首页

## 5.1 页面目标

教师登录后快速了解当前班级教学状态，重点回答：

```text
当前教到哪里？
学生完成得怎么样？
有哪些事情需要立即处理？
```

## 5.2 页面控件

### A. 教学上下文

| 控件 | 功能 |
|---|---|
| 学期选择器 | 切换当前学期 |
| 课程选择器 | 切换当前课程 |
| 班级选择器 | 切换当前教学班 |
| 刷新按钮 | 重新加载当前上下文数据 |

### B. 数据概览卡片

| 控件 | 功能 |
|---|---|
| 班级人数卡片 | 显示当前班级学生人数 |
| 进行中任务卡片 | 显示当前正在进行的任务数 |
| 平均完成率卡片 | 显示当前班级任务平均完成率 |
| 逾期人数卡片 | 显示存在逾期任务的学生数 |
| 待审核 AI 卡片 | 显示待教师审核的 AI 诊断数 |
| 风险学生卡片 | 显示需要重点关注的学生数 |

所有卡片点击后必须进入对应明细页面。

### C. 今日待办

| 控件 | 功能 |
|---|---|
| 待办列表 | 显示即将截止、学生逾期、AI 审核和教师反馈事项 |
| 待办标签 | 区分任务、学生、AI 和反馈类型 |
| 立即处理按钮 | 跳转到对应页面 |
| 标记已处理按钮 | 将待办标记为已处理 |

### D. 最近任务

| 控件 | 功能 |
|---|---|
| 最近任务表格 | 显示最近发布任务 |
| 完成进度条 | 显示任务完成比例 |
| 截止时间 | 显示剩余时间 |
| 查看监控按钮 | 进入任务监控 |
| 查看任务按钮 | 进入任务详情 |

### E. 班级学情摘要

| 控件 | 功能 |
|---|---|
| 完成率趋势图 | 展示近期完成率变化 |
| 高频错误排行 | 展示班级最常见错误 |
| 薄弱知识点列表 | 展示班级掌握较差知识点 |
| 查看完整分析按钮 | 进入学情诊断页面 |

## 5.3 学生端联动

该页面只读取学生端产生的数据，不直接修改学生数据：

- 学生任务进度
- 学生答题和提交
- AI 诊断
- 提示使用
- 学习画像
- 学习事件

## 6.1 子页面：课程与班级

查看教师负责的课程、班级和学生，不承担管理员的行政班创建职责。

### 页面控件

| 控件 | 功能 |
|---|---|
| 学期筛选器 | 按学期筛选课程 |
| 课程搜索框 | 按课程名称搜索 |
| 教学班卡片 | 展示课程、班级、学生数和任务数 |
| 查看班级按钮 | 进入班级详情 |
| 查看学生按钮 | 展开学生名单 |
| 查看学情按钮 | 进入班级学情 |
| 编辑课程说明按钮 | 修改教师可编辑的课程教学说明 |

### 学生名单控件

| 控件 | 功能 |
|---|---|
| 学生搜索框 | 按姓名或学号搜索 |
| 风险筛选器 | 筛选正常、关注和高风险学生 |
| 学生表格 | 展示学生基础学习状态 |
| 查看学生学情按钮 | 进入学生详情 |
| 查看任务记录按钮 | 查看该学生课程任务 |

### 学生端联动

- 教师查看的是学生端真实成员和学习进度
- 教师不能直接删除学生或修改学生行政班

## 6.2 子页面：课程大纲

### 页面目标

编排课程章节、知识点和实验任务顺序，使任务、资料和画像都绑定到统一知识结构。

### 页面控件

| 控件 | 功能 |
|---|---|
| 章节树 | 展示课程章节层级 |
| 新建章节按钮 | 创建课程章节 |
| 编辑章节按钮 | 修改章节名称和说明 |
| 拖拽排序 | 调整章节顺序 |
| 知识点列表 | 展示章节下知识点 |
| 新建知识点按钮 | 创建知识点 |
| 知识点标签 | 标识知识点类型和难度 |
| 关联资料按钮 | 将资料关联到知识点 |
| 关联任务按钮 | 将任务关联到知识点 |
| 章节预览按钮 | 预览学生端课程结构 |

### 学生端联动

课程大纲决定：

- 学生端课程章节结构
- 自主学习知识点列表
- AI 导师可检索的知识范围
- 学习画像中的知识点维度
- 任务和错误的知识归属

### 开发边界

- 已被正式任务使用的知识点不得直接删除
- 删除前必须检查任务、资料和画像关联
- 第一版不做复杂知识图谱，只做章节—知识点层级

| 版本记录 | 查看资料历史版本 |
| 引用次数 | 查看 AI 和任务使用次数 |

## 7.3 学生端联动

启用且学生可见的资料进入：

- 学生自主学习
- 学生收藏夹
- AI 导师引用
- AI 诊断知识来源
- 任务相关资料

## 7.4 开发边界

- 停用资料不参与新的 AI 检索
- 历史 AI 诊断中的引用不能被抹除
- 删除资料前必须检查历史引用
- 第一版可先做文本资料和元数据管理，文件自动切片放到后续

- 第一版不承诺支持任意 C++ 编程题
- 通用判题模板系统放到后续阶段

# 十五、必须遵守的开发规范

## 15.1 权限

- 教师只能访问自己负责的教学关系
- 教师接口优先使用 `teaching_assignment_id`
- 不能只使用 `course_id` 判断数据范围
- 学生不能访问任何教师接口
- 教师不能查看其他教师班级学生数据
- 所有导出也必须执行权限校验

## 15.2 数据

- 不允许前端写死课程 ID、班级 ID 或学生 ID
- 教师端和学生端必须读取同一份任务和提交数据
- 发布任务后必须初始化班级所有学生进度
- 历史提交、成绩、AI 诊断和教师反馈不得物理覆盖
- 已发布任务修改必须生成版本或受到限制
- 所有关键写操作必须记录审计日志

## 15.3 AI

- 所有 AI 输出使用结构化 Schema
- 保存模型名称、提示词版本、置信度和引用
- AI 失败时保留规则兜底
- AI 不直接发布正式题目
- AI 不直接修改成绩
- AI 不直接修改画像分数
- 教师审核不能覆盖原始 AI 输出
- 学生端不得看到隐藏测试和内部审核信息

## 15.4 评测

- 系统判题结果优先于 AI 判断
- AI 负责解释错误，不负责替代执行器
- 客观题答案由规则自动判定
- 编程题必须通过沙箱和测试用例判定
- 教师创建编程任务时只能使用系统支持模板
- 所有测试用例发布前必须验证

## 15.5 页面与接口

- 教师端使用独立布局和路由
- 学生端保持现有学习布局
- 两端共用业务 API 和数据模型
- 列表接口必须分页
- 前后端字段和状态枚举必须统一
- 模块开发前先确定公共响应格式
- 不允许开发者为单个页面私自新增重复业务表

# 十八、推荐开发顺序

```text
第一阶段
教师端基础
→ 课程与班级
→ 学生名单
→ 现有提交查看

第二阶段
任务管理
→ 客观题编辑
→ 任务发布
→ 学生端任务联动

第三阶段
提交监控
→ 教师反馈
→ AI 审核
→ 学生端反馈联动

第四阶段
班级学情
→ 个体诊断
→ 风险预警
→ 教学改进

第五阶段
模板化编程任务
→ 资料上传
→ RAG
→ 教学效果报告
```

不要先做：

- 任意编程题通用判题
- 复杂多智能体
- 自动认定抄袭
- AI 自动发布正式题目
- AI 自动修改学生成绩
- 与当前教学闭环无关的复杂后台

# 十九、最终验收主流程

```text
教师登录
→ 选择课程和班级
→ 编排课程章节和知识点
→ 上传课程资料
→ 创建客观题或模板化编程任务
→ 设置评分、测试和提示
→ 发布任务
→ 学生在学生端接收任务
→ 学生完成并提交
→ 系统自动判题和生成 AI 诊断
→ 教师在任务监控中查看提交
→ 教师审核 AI 并发布反馈
→ 学生查看教师确认后的诊断
→ 教师查看班级和学生学情
→ 教师生成教学建议并调整下一阶段任务
```

达到以上流程后，CodeTrack 才真正形成一个统一的：

```text
课程教学
＋ 学生学习
＋ 自动评测
＋ AI 辅导
＋ 学情诊断
＋ 教学改进
```

双端教学闭环平台。
