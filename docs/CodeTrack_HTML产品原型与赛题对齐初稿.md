# CodeTrack HTML 产品原型与赛题对齐初稿

> 版本：V0.1  
> 用途：用于团队讨论产品原型、业务流程、页面状态和赛题对齐，不作为最终开发文档。  
> 对齐来源：CodeTrack 当前项目、会议纪要综合梳理、赛题《面向一流学科建设的学科垂类大模型与创新应用开发》中的第三大项“题目介绍”和第五大项“答题要求”。

## 0. 编写口径

本原型先聚焦一个可讲清楚、可演示、可验证的场景：

> 面向计算机类专业基础课程的数据结构与程序设计助学场景。

本阶段不把系统扩展成完整教务平台、完整科研助手或全校级管理平台。教师端只保留与学生助学闭环直接相关的建课、资源、知识库、任务发布和学情分析流程；助研能力仅在赛题对齐中作为后续拓展入口说明。

如果后续团队确认必须同时覆盖助教或助研，也应在当前学生助学闭环稳定后，再新增独立流程。

## 1. 赛题第三大项对齐：题目介绍中的场景与价值

### 1.1 赛题核心理解

赛题强调的是：

- 大模型深度融入高校教育教学、科研和创新实践。
- 面向特定学科研发垂类大模型。
- 基于真实教学研场景开发智能体等创新应用。
- 重点服务教师教学创新、学生个性化学习、科研全流程提效。
- 通过“人工智能 + 学科”实现从学知识到强能力的转变。

CodeTrack 对齐方式：

| 赛题要求 | CodeTrack 原型对齐 |
| --- | --- |
| 特定学科 | 选择计算机类专业基础课，首门课程为“数据结构与程序设计基础” |
| 教学真实场景 | 教师建课、挂资源、发任务、看学情、调整教学 |
| 学生真实痛点 | 代码调试困难、概念理解浅、错因不清楚、不会规划复习路径 |
| 智能体应用 | 代码诊断智能体、渐进式提示智能体、概念导师智能体、学习画像智能体、引用守卫智能体 |
| 从学知识到强能力 | 不只答题，而是通过任务实践、AI 诊断、画像更新、资料沉淀和下一步推荐形成能力成长链路 |

### 1.2 原型中的主场景

本原型主场景不做泛教育平台，而是选择以下真实教学痛点：

> 学生在数据结构编程任务中经常出现边界条件、指针、递归和栈队列应用错误；教师难以及时逐个诊断错误原因，学生也缺少个性化复习路径和可追溯的专业解释。

因此原型围绕一条主闭环展开：

```text
教师配置课程资源和任务
-> 学生进入课程任务
-> 编写并提交代码
-> 系统运行测试
-> AI 基于测试结果、课程知识库和学生画像生成诊断
-> 学生按层级获取提示并再次提交
-> 通过后生成学习总结
-> 更新学习画像
-> 保存学习资料
-> 推荐下一步学习内容
-> 教师查看班级学情并调整教学
```

## 2. 赛题第五大项对齐：答题要求

### 2.1 助学场景对齐

赛题第五大项明确要求作品满足特定学科中一个或多个真实教学或科研场景需求。CodeTrack 本轮原型优先选择“助学场景”，因为当前项目已有代码评测、AI 诊断、分层提示和学习画像基础。

| 赛题助学要求 | 原型功能落点 |
| --- | --- |
| 学习路径规划 | 学习首页显示今日任务、薄弱点、推荐下一步；自主学习页按知识点生成路径 |
| 知识问答与讲解 | AI 助学页围绕链表、栈与队列、二叉树等知识点答疑，展示引用来源 |
| 代码调试 | 任务工作台提交代码后，显示测试结果、AI 诊断、错因类型和分层提示 |
| 概念辨析 | 自主学习页支持概念讲解、例题、练习题、知识卡片 |
| 学习过程陪伴 | AI 助学结合学习画像给出复习建议、错因归因和下一步动作 |
| 个性化适配 | 根据任务提交、测试结果、提示使用、自主学习和资料保存更新画像 |

### 2.2 助教场景的有限对齐

助教场景不作为本轮主线，但原型中保留与助学闭环强相关的教师端流程：

| 赛题助教要求 | 原型处理 |
| --- | --- |
| 智能备课 | 首版只展示“导入课程大纲/教材资源后生成章节建议”的入口，不展开完整 Word/PPT 生成 |
| 作业与试题批改 | 编程任务由系统自动评测；客观练习可展示自动判分状态 |
| 学情精准诊断 | 教师端展示班级任务完成率、薄弱知识点、高频错因、风险学生和调整建议 |

### 2.3 助研场景的处理边界

助研不是当前 CodeTrack 学生助学闭环的必要环节。本轮 HTML 原型不展开论文写作、投稿匹配、项目申报等完整科研流程。

原型中只在总览页或后续规划中标注：

```text
后续可基于同一学科知识库和智能体框架扩展助研场景。
```

不要在当前原型里新增助研细页，避免主线失焦。

### 2.4 技术实现建议对齐

| 赛题技术建议 | 原型表达方式 |
| --- | --- |
| 知识库构建 | 教师端资源与知识点绑定；学生端 AI 回答展示课程资料引用 |
| 模型微调 | 原型中标注为后续技术路线，不伪装为已完成 |
| RAG | AI 答疑和诊断展示“检索课程知识源 -> 生成答案 -> 引用来源”的流程 |
| 智能工作流编排 | 用流程图展示诊断、提示、画像、资料生成等多个智能体协作 |
| 多模态交互 | 首版只支持文本、代码、PPT/文档资源引用说明，不做真实多模态解析 |
| 场景化开发 | 所有页面围绕数据结构课程任务和学生学习闭环展开 |

### 2.5 核心功能要求对齐

| 赛题核心功能要求 | 原型必须体现 |
| --- | --- |
| 1. 深度贴合场景需求 | 每个页面都说明当前角色、业务状态、用户动作和系统反馈 |
| 2. 交互自然流畅 | AI 助学支持多轮追问入口，回答后提供保存、生成练习、跳转任务等动作 |
| 3. 知识权威可信 | 所有专业回答必须显示课程知识源、章节或资源来源 |
| 4. 内容可追溯 | AI 诊断、AI 答疑、资料生成均展示引用来源、置信度和 AI 生成标识 |
| 5. 可复制与可推广 | 原型说明该闭环可复制到其他计算机基础课，如计算机网络、组成原理 |
| 8. 个性化与自适应 | 学习画像影响推荐路径、提示策略和资料生成建议 |

本轮不强行覆盖第 6 项“生成内容多元性”和第 7 项“复杂问题求解”的全部深度能力，只在自主学习中用 PPT 大纲、思维导图、练习题等轻量资料生成进行初步体现。

## 3. HTML 原型目录结构

建议采用零成本实现方式：

```text
prototype/
├── index.html
├── flow.html
├── teacher.html
├── student.html
├── assets/
│   ├── style.css
│   └── app.js
└── data/
    └── mock.js
```

### 3.1 index.html：原型入口

作用：让评审或老师一进来就知道作品是什么、面向谁、演示哪条业务线。

核心内容：

- 作品名称：CodeTrack 学科垂类 AI 助学系统。
- 学科场景：计算机类专业，数据结构与程序设计基础。
- 角色入口：学生端、教师端。
- 演示阶段入口：首次使用、已配置课程、已发布任务、已产生学情。
- 赛题对齐提示：助学主线，有限覆盖助教，保留助研扩展。

页面状态：

```text
状态 1：原型总览
状态 2：选择教师端流程
状态 3：选择学生端流程
状态 4：查看业务总流程
```

### 3.2 flow.html：业务流程与数据流

作用：解释业务怎么跑，不只是展示页面。

必须包含三张图或三块流程：

```text
1. 总业务闭环
教师建课 -> 学生学习 -> 系统采集 -> AI 分析 -> 双端反馈 -> 教学调整

2. 学生助学闭环
学习首页 -> 课程任务 -> 编程工作区 -> AI 诊断 -> 分层提示 -> 总结 -> 画像 -> 资料 -> 推荐

3. AI 工作流
页面上下文 + 学生画像 + 课程知识库 + 测试结果
-> 代码诊断智能体
-> 渐进式提示智能体
-> 引用守卫
-> 学习画像更新
-> 学习资料生成
```

每个流程节点旁边标注：

```text
输入数据
用户动作
系统输出
AI 是否参与
是否需要引用来源
```

### 3.3 teacher.html：教师端原型

教师端只做与学生助学闭环相关的流程，不做完整教务系统。

#### T0 教师首次登录：无课程

进入条件：

```text
教师首次登录，系统中没有创建任何课程。
```

页面内容：

- 空状态提示：暂无课程。
- 主按钮：创建课程。
- 次按钮：导入课程资料、查看示例课程。
- 说明：课程是资源、知识库、任务和学情分析的前置条件。

业务说明区：

| 项目 | 内容 |
| --- | --- |
| 当前角色 | 教师 |
| 当前状态 | 首次登录，无课程 |
| 用户动作 | 点击创建课程 |
| 系统反馈 | 进入课程创建表单 |
| 数据来源 | 教师手动填写课程信息 |
| AI 参与 | 暂不参与 |
| 下一步 | 创建课程并绑定学生或班级 |

#### T1 创建课程

表单字段：

- 课程名称：数据结构与程序设计基础。
- 面向专业：软件工程 / 计算机科学与技术。
- 学期：2026 秋季。
- 课程简介。
- 教学目标。
- 课程知识范围：链表、栈与队列、二叉树。

系统反馈：

```text
课程创建成功，进入课程工作台。
```

#### T2 添加学生或绑定班级

页面状态：

```text
课程已创建，但暂无学生。
```

核心动作：

- 手动添加学生。
- 批量导入学生。
- 绑定已有班级。

原型边界：

```text
不实现真实导入，只展示导入入口和导入后的学生列表状态。
```

#### T3 建设章节、资源和课程知识库

核心页面块：

- 章节列表。
- 资源列表：PPT、教材片段、代码样例、练习说明。
- 知识点列表：链表、栈与队列、二叉树。
- 资源绑定知识点。

必须体现：

```text
AI 回答的来源来自教师配置的课程资源和知识点绑定。
```

#### T4 发布课程任务

任务字段：

- 任务名称：单链表指定位置节点删除。
- 任务类型：编程任务。
- 关联知识点：链表、边界处理、指针。
- 难度层级：基础。
- 是否允许三级提示：允许 / 不允许。
- 截止时间。
- 发布对象：软件工程 1 班。

系统反馈：

```text
发布后，学生端课程任务列表出现该任务。
```

#### T5 查看学情分析

进入条件：

```text
学生产生提交、测试结果、AI 诊断和提示使用记录。
```

展示内容：

- 任务完成率。
- 测试通过率。
- 薄弱知识点 Top 3。
- 高频错因。
- 提示依赖程度。
- 需要关注的学生。
- AI 教学调整建议。

AI 输出必须标注：

- AI 生成内容。
- 数据依据。
- 置信度。
- 建议下一步。

## 4. student.html：学生端原型

学生端是本轮主线，页面状态必须完整。

### S0 学生首次登录：未加入课程

进入条件：

```text
学生首次登录，尚未加入任何课程。
```

页面内容：

- 空状态：暂无课程任务。
- 主按钮：加入课程。
- 次入口：进入自主学习。
- 说明：课堂学习需要教师建课或课程码，自主学习不依赖教师下发任务。

业务说明区：

| 项目 | 内容 |
| --- | --- |
| 当前角色 | 学生 |
| 当前状态 | 未加入课程 |
| 用户动作 | 输入课程码或进入自主学习 |
| 系统反馈 | 加入课程后显示课程任务；自学区直接可用 |
| 数据来源 | 教师课程、学生自主选择 |
| AI 参与 | 自学区可参与 |
| 下一步 | 查看课程任务或选择知识点学习 |

### S1 学习首页：已加入课程

页面内容：

- 今日任务。
- 当前课程进度。
- 薄弱知识点。
- 推荐下一步。
- 最近保存资料。
- AI 快捷提问。

推荐逻辑：

```text
即将截止任务
-> 上次未通过任务
-> 画像薄弱知识点
-> 最近学习但未巩固知识点
-> 系统默认路径
```

### S2 课程任务列表

页面内容：

- 课程筛选。
- 任务状态筛选。
- 任务卡片。
- 截止提醒。

任务卡字段：

- 任务标题。
- 所属课程。
- 发布教师。
- 知识点。
- 难度。
- 截止时间。
- 当前状态。
- 最近一次提交摘要。
- 进入任务按钮。

### S3 编程任务工作台

页面布局：

```text
左侧：任务说明、知识点、公开样例
中间：代码编辑器、运行、提交
右侧：系统验证、AI 诊断、分层提示、引用来源
```

关键要求：

- 系统测试结果先展示，AI 解释后展示。
- AI 不覆盖工具事实。
- 考核模式不直接给完整答案。
- 诊断必须展示引用来源、置信度、是否需要教师复核。

### S4 提交失败：AI 诊断与分层提示

触发条件：

```text
学生提交代码后，部分测试未通过。
```

页面展示：

- 编译状态。
- 测试通过情况。
- 失败用例摘要。
- 错因类型。
- AI 解释。
- 引用来源。
- 一级提示按钮。
- 二级提示按钮。
- 三级提示按钮。

分层提示规则：

```text
一级：指出知识点和方向
二级：指出可能的逻辑分支或边界条件
三级：给出修复思路或局部伪代码，不直接贴完整答案
```

### S5 再次提交通过：总结与画像更新

触发条件：

```text
学生修改代码并通过必要测试。
```

页面展示：

- 本次任务总结。
- 主要错因。
- 使用过的提示。
- 关联知识点。
- 可保存的学习笔记。
- 画像更新提示。
- 下一步推荐。

系统反馈：

```text
任务总结保存到“我的资料”，学习画像更新，首页推荐发生变化。
```

### S6 自主学习

进入方式：

- 学生无课程时也可进入。
- 学生有课程时可从薄弱知识点跳转进入。

页面内容：

- 知识点选择：链表、栈与队列、二叉树。
- 生成类型：概念讲解、练习题、复习笔记、知识卡片、思维导图、PPT 大纲。
- 引用来源。
- 保存到我的资料。
- 生成练习。

原型说明：

```text
首版使用规则或 mock 内容演示结构，不宣称真实完成模型微调。
```

### S7 AI 助学

页面内容：

- 对话区。
- 当前上下文。
- 学习画像摘要。
- 引用来源。
- 下一步动作。

AI 回答结构：

```text
结论
-> 分步解释
-> 与当前画像相关的提醒
-> 引用来源
-> 下一步动作
```

每条 AI 回答必须显示：

- AI 生成内容。
- 是否结合画像。
- 置信度。
- 引用来源。
- 可执行动作。

### S8 我的资料

资料来源：

- 任务学习总结。
- AI 回答。
- 自主学习生成内容。
- 错题归因。
- 思维导图。
- PPT 大纲。

资料字段：

- 标题。
- 类型。
- 关联知识点。
- 来源页面。
- AI 生成标识。
- 引用来源。
- 创建时间。
- 学生备注。

## 6. assets/app.js：交互设计建议

只做轻量交互，不做真实后端。

必须支持：

- 角色切换：教师 / 学生。
- 阶段切换：首次使用 / 已配置课程 / 已发布任务 / 已产生学情。
- 学生任务状态切换：未提交 / 提交失败 / 查看提示 / 再次提交通过。
- AI 回答展开引用来源。
- 保存资料后的状态变化。

不做：

- 真实登录。
- 真实数据库。
- 真实 AI 接口。
- 真实文件上传。
- 真实 PPT 或 Word 导出。

## 7. 原型演示脚本

### 7.1 开场

```text
CodeTrack 面向计算机类专业基础课程，选择“数据结构与程序设计基础”作为首个垂类场景。
它不是普通判题平台，而是围绕专业课学习任务，打通教师配置、学生实践、AI 诊断、画像更新和个性化推荐的助学闭环。
```

### 7.2 教师端演示

```text
教师首次登录没有课程，系统引导创建课程。
课程创建后，教师添加学生、建立章节资源，并把 PPT、讲义和代码样例绑定到知识点。
随后教师发布一个“单链表指定位置节点删除”的编程任务，设置知识点、难度和提示规则。
学生提交后，教师端能看到任务完成率、薄弱知识点、高频错因和 AI 教学调整建议。
```

### 7.3 学生端演示

```text
学生加入课程后，首页显示今日任务、薄弱点和推荐下一步。
学生进入编程任务工作台，提交代码后先看到系统测试结果，再看到 AI 基于课程知识库和测试证据生成的诊断。
学生逐层获取提示，修改后再次提交通过。
通过后，系统生成学习总结，更新学习画像，并将总结保存到我的资料。
如果学生想主动学习，也可以进入自主学习区，选择链表、栈与队列或二叉树生成讲解、练习、卡片和 PPT 大纲。
```

### 7.4 赛题对齐收束

```text
本作品对齐赛题中的助学场景，重点解决专业学习中的代码调试、概念理解、错因归因和路径规划问题。
技术上预留学科知识库、RAG、智能体工作流和引用守卫机制。
内容输出展示来源、置信度和 AI 生成标识，保证可追溯、可核查。
```

## 8. 本轮明确不做的内容

为避免原型失焦，本轮不做以下内容：

- 完整科研助手流程。
- 完整管理员后台。
- 真实模型微调。
- 真实外部平台接口。
- 真实文件上传解析。
- 真实 PPT/Word 二进制导出。
- 签到、排行榜、积分商城、社交社区。
- 多学科通用平台。

这些可以放在“后续拓展”或“技术路线”中说明。

## 9. 待确认事项

以下问题需要团队或老师确认后再细化：

1. 首个专业是否确定为软件工程、计算机科学与技术、人工智能或物联网工程？
2. 首门课程是否继续使用“数据结构与程序设计基础”？
3. 教师端在本轮原型中是否必须展示 AI 教学设计、AI PPT 和 AI 组卷，还是只放入口？
4. 管理员端是否必须出页面？如果必须，是否只做模型、知识库和用户权限的概览？
5. 助研是否必须在原型中出现？如果必须，建议只放一页“后续扩展能力”，不进入主流程。
6. 是否要对接星火学科大模型平台作为展示口径，还是只写“可接入星火或开源模型”？
7. 参赛作品最终是否以可运行系统为主，还是先以 HTML 原型和演示视频作为阶段交付？

## 10. 下一步工作建议

第一步，按本目录创建 HTML 原型骨架。

第二步，先完成 `index.html` 和 `flow.html`，把赛题对齐和业务闭环讲清楚。

第三步，完成 `student.html`，重点做学生首次登录、学习首页、任务工作台、AI 诊断、画像更新和我的资料。

第四步，完成 `teacher.html`，只做建课、资源、任务发布和学情分析。

第五步，统一所有页面的业务说明区，确保每个状态都有：

```text
当前角色
当前状态
用户动作
系统反馈
数据来源
AI 是否参与
引用来源要求
下一步跳转
```

本轮原型的目标不是页面数量最多，而是让评审清楚看到：

```text
CodeTrack 如何满足赛题中的特定学科、真实场景、智能体应用、个性化助学、知识可信和内容可追溯要求。
```
