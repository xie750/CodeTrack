# CodeTrack 学习画像与岗位胜任力对齐框架

> 目标：把学生的学习数据转化为能力证据，再与目标岗位要求对齐，判断学生当前能胜任什么、还缺什么，以及下一步应完成什么任务。

---

## 一、画像层级

```text
L1 原始学习数据
→ L2 能力证据
→ L3 学习画像
→ L4 学生能力画像
→ L5 岗位胜任力画像
→ L6 个性化提升路径
```

| 层级 | 作用 |
|---|---|
| L1 原始学习数据 | 记录课程、练习、代码、测试、项目、Git、AI使用等行为 |
| L2 能力证据 | 将行为转化为“这项活动能够证明什么能力” |
| L3 学习画像 | 描述学生学得怎么样、知识掌握如何、学习过程如何 |
| L4 学生能力画像 | 描述学生实际具备哪些知识、开发、调试和工程能力 |
| L5 岗位胜任力画像 | 将学生能力与目标岗位模型比较，确定当前岗位阶段 |
| L6 提升路径 | 根据差距推荐课程、专项任务、项目和验证任务 |

---

## 二、核心画像维度

### 1. 学习画像

- 学习投入
- 学习进度
- 知识掌握
- 编程基础
- 解题与调试
- 学习习惯

### 2. 能力画像

- 专业知识
- 功能开发
- 问题解决
- 测试与调试
- 工程实践
- 项目交付
- 迁移与解释

### 3. 岗位胜任力画像

- 岗位核心技能
- 岗位典型任务
- 工程实践要求
- 项目与作品证据
- 通用职业能力
- 能力差距与当前阶段

---

## 三、两个核心业务场景

### 场景A：知识高，实践证据不足

表现：课程、测验和刷题成绩较高，但缺少独立功能、完整项目、测试、Git和部署记录。

诊断：

> 知识基础较强，但实践证据不足，暂时不能确认具备岗位交付能力。

处理：

```text
推荐岗位型项目
→ 采集开发全过程
→ 形成项目与工程证据
→ 重新评估岗位阶段
```

### 场景B：实践高，知识掌握较弱

表现：能完成项目或功能，但知识测评较低，难以解释原理，迁移到新场景时不稳定。

诊断：

> 已具备常规任务实践能力，但知识稳定性和迁移能力需要验证。

处理：

```text
项目解释验证
+ 需求变更任务
+ 陌生故障排查
+ 核心知识补齐
→ 判断能力是否真实、稳定、可迁移
```

## 四、量化设计逻辑

岗位胜任力不能由学习分数直接平均得到，应采用：

> **维度评分 + 能力证据 + 核心门槛**

每项岗位技能至少包含：

| 数据项 | 含义 |
|---|---|
| 知识掌握度 | 是否理解核心概念 |
| 任务完成度 | 是否能完成对应功能 |
| 工程质量 | 测试、规范、Git、文档和部署情况 |
| 迁移能力 | 能否修改需求、解释方案和处理新问题 |
| 证据强度 | 证据来自课程、练习、功能、项目还是企业型任务 |
| 独立程度 | 独立完成还是依赖模板、团队或AI |
| 最近验证时间 | 能力是否仍然有效 |

概念计算：

```text
单项技能达成度
= 知识表现
+ 任务表现
+ 工程表现
+ 迁移表现
再结合证据强度和独立程度修正
```

最终岗位阶段：

```text
综合能力结果
∩ 核心知识门槛
∩ 岗位任务门槛
∩ 项目证据门槛
= 当前可达到的最高阶段
```

因此，高知识不能抵消项目缺失；高实践也不能完全抵消核心知识和迁移能力不足。

## 五、岗位阶段

| 阶段 | 说明 |
|---|---|
| P0 尚未对齐 | 尚未确定岗位或缺少岗位基础 |
| P1 基础学习 | 主要具备课程和练习证据 |
| P2 任务执行 | 能在指导下完成明确的小型任务 |
| P3 独立交付 | 能独立完成功能模块并完成测试和调试 |
| P4 岗位准备 | 能完成接近企业要求的完整项目 |
| P5 实战验证 | 已在团队或企业型环境中稳定完成任务 |

P3表示能够独立完成边界明确的开发任务；P4才表示基本达到初级岗位准备标准。

## 六、后端数据关系

```text
学生
→ 学习事件
→ 任务或项目
→ 对应技能
→ 形成能力证据
→ 更新能力等级
→ 对比岗位技能要求
→ 生成岗位阶段和提升建议
```

建议保留的核心数据实体：

| 数据实体 | 主要内容 |
|---|---|
| learning_event | 学习、运行、提交、测试、修复、Git、AI使用等原始事件 |
| skill | 统一技能节点 |
| task_skill_map | 每个课程、练习或项目能够证明哪些技能 |
| ability_evidence | 学生针对某项技能形成的证据 |
| student_skill | 学生当前技能等级与更新时间 |
| job_profile | 目标岗位及岗位能力模型 |
| job_skill_requirement | 岗位所需技能、等级和重要程度 |
| profile_snapshot | 学习画像、能力画像和岗位阶段快照 |
| recommendation | 根据能力差距生成的下一步任务 |

---

## 七、数据沉淀闭环

```text
岗位技能标准
→ 配置对应课程、练习和实践任务
→ 学生完成任务并产生事件数据
→ 事件转化为能力证据
→ 证据更新学生能力画像
→ 与目标岗位进行对齐
→ 识别“能力不足”或“证据不足”
→ 推荐下一步学习或实践任务
→ 新证据再次更新画像
```

核心原则：

> 不根据少量分数直接判断学生能力，而是根据知识、任务、项目和工程证据共同判断其能够胜任的岗位范围。
