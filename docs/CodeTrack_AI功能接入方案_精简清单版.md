## 2. 总体建设思路

- [ ] 不先做复杂多智能体系统
- [ ] 优先采用“固定工作流 + 单智能体 + RAG”
- [ ] 确定性任务使用工作流
- [ ] 开放式问答使用智能体
- [ ] 所有 AI 功能统一接入模型网关
- [ ] 所有 AI 输出使用结构化 Schema
- [ ] 所有 AI 回答保留引用、置信度和运行记录
- [ ] AI 不直接访问数据库，通过受控工具调用业务数据

推荐结构：

```text
前端页面
→ FastAPI AI 接口
→ 上下文组装
→ 知识检索
→ 工作流或智能体
→ 安全校验
→ 数据保存
→ 学习画像更新
```

## 4. 核心 AI 工作流

### 4.1 代码诊断工作流

```text
提交代码
→ 沙箱编译
→ 执行测试
→ 提取错误证据
→ 检索课程知识
→ AI 结构化诊断
→ 引用校验
→ 答案泄露检查
→ 保存诊断
→ 生成渐进提示
→ 更新学习画像
```

### 4.2 AI 导师工作流

```text
学生提问
→ 判断问题类型
→ 获取页面上下文
→ 获取学生画像
→ 获取近期学习记录
→ 检索课程资料
→ 调用对应工具
→ 生成回答
→ 校验引用和置信度
→ 保存对话
```

### 4.3 学习资料生成工作流

```text
选择知识点
→ 选择资料类型
→ 获取学生画像
→ 检索课程知识
→ 生成结构化资料
→ 内容校验
→ 学生预览
→ 保存到资料库
→ 记录学习事件
```

### 4.4 错题巩固工作流

```text
提交答案
→ 系统判题
→ 提取错误类型
→ AI 解释
→ 检索知识来源
→ 生成相似题
→ 校验题目
→ 完成巩固
→ 更新画像
```

## 7. 技术选型

### 7.1 第一阶段

- [x] FastAPI
- [x] SQLAlchemy
- [x] 当前模型网关
- [ ] Pydantic Schema
- [ ] 自定义工作流服务
- [ ] SSE 流式输出

推荐原因：

- 与当前项目兼容
- 调试简单
- 业务状态统一
- 权限容易控制
- 不增加过多框架复杂度

### 7.2 后续可选

#### LangGraph

适用于：

- [ ] 工作流暂停和恢复
- [ ] 教师审核节点
- [ ] 多步骤状态持久化
- [ ] 多智能体协作
- [ ] 复杂工具调用
- [ ] 从失败节点继续执行

#### Dify

适用于：

- [ ] 快速验证提示词
- [ ] 快速测试 RAG
- [ ] 快速搭建演示工作流

限制：

- 不建议作为项目核心业务后端
- 避免业务数据和 AI 状态分散

#### n8n

适用于外围自动化：

- [ ] 定时生成学习周报
- [ ] 课程资料导入
- [ ] 教师消息通知
- [ ] 班级数据汇总
- [ ] 外部邮件和消息推送

不适用于：

- 实时代码诊断
- 核心学习业务流程
