# 算法应用设计

## 1. 定位

本项目中的“算法应用”不是单独给学生展示的功能入口，也不是为了页面上出现“算法”两个字。

它是学生助学闭环中的内部决策能力：

```text
学习行为数据
-> 学习画像更新
-> 薄弱点和错因识别
-> 候选学习动作生成
-> 推荐排序
-> 前端展示下一步建议
```

前端只展示学生能理解的任务、建议和原因；底层算法规则、权重和排序细节留在后端。

## 2. 最有价值的落点

首版最有价值的算法应用是：

> 学习画像驱动的个性化下一步推荐算法。

它服务于现有 P0 页面和闭环：

- 学习首页：决定“推荐学习”和“继续学习”的优先顺序。
- 学习画像：把薄弱知识点、高频错因、提示依赖和任务完成情况转成可行动建议。
- 任务工作台：提交、诊断、提示、通过后产生画像信号。
- 自主学习：根据薄弱点推荐复盘、练习或资料生成。
- AI 助学：读取推荐和画像，让回答更贴合当前学生。

不建议新增“算法应用”一级导航。那会把产品变成展示算法的页面，而不是用算法改善助学效果。

## 3. 输入信号

推荐算法使用以下内部信号：

| 信号 | 来源 | 用途 |
| --- | --- | --- |
| 任务状态 | `student_task_progress` | 判断未开始、进行中、待修正、已完成 |
| 截止时间 | `task_assignments.deadline` | 判断任务紧急程度 |
| 测试通过情况 | `passed_count / total_required_count` | 判断任务完成缺口 |
| 最高提示等级 | `highest_hint_level` | 判断提示依赖和自主完成程度 |
| 知识点掌握度 | `learner_knowledge_states.mastery_score` | 识别薄弱知识点 |
| 错因统计 | `learner_error_stats` | 判断某类错误是否持续出现 |
| 学习事件 | `learner_events` | 判断最近学习行为和待巩固知识点 |
| 已有推荐 | `recommendations` | 与人工配置或历史推荐合并排序 |

这些信号都来自现有助学链路，不需要学生额外填写问卷。

## 4. 处理逻辑

第一版采用可解释的规则评分，不直接依赖黑盒模型排序。

推荐候选分两类：

1. 任务候选：未完成、待修正、即将截止或与薄弱点相关的任务。
2. 复盘候选：掌握度低于稳定线、近期出现错因或刚产生学习事件的知识点。

内部排序考虑：

```text
任务状态权重
+ 截止紧急度
+ 测试完成缺口
+ 薄弱知识点匹配
+ 高频错因压力
+ 提示依赖信号
+ 最近学习但未巩固信号
```

权重结果只用于排序，不直接展示给学生。

## 5. 输出契约

推荐结果继续使用现有结构：

```json
{
  "id": "rec_xxx",
  "title": "复盘 链表边界处理",
  "reason": "链表边界处理的掌握度仍低于稳定线，建议先做专项复盘，再通过练习验证。",
  "priority": 42,
  "related_task_id": "task_linked_list_delete_001",
  "related_knowledge_points": ["链表", "边界处理"],
  "suggested_action": "OPEN_SELF_STUDY"
}
```

说明：

- `priority` 是后端排序字段，不需要在学生端显式展示。
- `reason` 只解释学习依据，不暴露具体公式。
- `suggested_action` 必须来自前端动作白名单。
- 推荐必须能关联到任务或知识点，避免空泛建议。

## 6. 与 AI 的关系

算法推荐和大模型分工如下：

- 算法负责排序、边界、稳定性和可复现。
- AI 负责把推荐结果组织成学生能理解的解释、计划或答疑。
- AI 不能绕过推荐算法直接修改任务、成绩或画像。
- AI 回答引用课程知识时仍必须经过引用校验。

因此，“算法应用”不是替代 AI，而是让 AI 助学更稳、更可解释。

## 7. 工程落点

当前推荐算法落在：

```text
backend/app/services/recommendation.py
```

接入位置：

- `backend/app/services/learner_profile.py`：画像序列化时合并算法推荐和已有推荐。
- `backend/app/services/question_workflow.py`：客观题提交后同步推荐留痕。
- `frontend/src/pages/LearningHome.tsx`：首页继续按 `profile.recommendations` 展示。
- `frontend/src/pages/LearningProfile.tsx`：画像页继续按推荐结果生成下一步建议。

后续如果接入机器学习模型、协同过滤或更复杂的排序模型，应先保持上述输出契约稳定。

## 8. 次级算法应用

任务工作台中的“算法演示”可以保留为次级应用。

它适合解释数据结构任务中的链表、栈、二叉树、BFS、DFS 等过程，但它主要提升学习体验，不承担产品主闭环的决策价值。

优先级建议：

```text
P0：画像驱动推荐算法
P1：知识检索和引用排序优化
P1：算法演示与题目结构自动匹配
P2：个性化练习难度自适应
```

## 9. 验收标准

首版算法应用完成后，应能演示：

- 学生提交任务或题组后，画像和推荐发生变化。
- 首页推荐优先显示未完成、待修正、即将截止或薄弱点相关内容。
- 推荐理由能说明学习依据，但不暴露权重公式。
- 推荐能跳转到任务、自主学习或练习生成等实际动作。
- AI 助学能读取画像和推荐结果，而不是给出泛泛学习建议。
- 没有足够数据时，系统使用默认学习路径或已有推荐兜底。
