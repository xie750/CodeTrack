# 语音控制功能调研与落地方案

## 1. 功能定位

语音控制不是新增一级页面，而是嵌入学生高频学习流程的辅助交互层。第一版重点放在题目作答工作区，让学生可以通过语音完成选择题作答、跳题、保存草稿和交卷，形成可演示的亮点：

```text
说出“第一题选 A，第二题选 B，下一题，交卷”
-> 浏览器识别语音文本
-> 命令解析器转换为结构化动作
-> 页面自动选择答案 / 跳转 / 保存 / 提交
-> 右侧面板显示识别文本和执行日志
```

该能力服务第二阶段“学生助学闭环”，尤其适合把 CodeTrack 从普通判题或题库平台区分出来：学生不仅能点选和输入，也能用自然口语驱动学习任务。

## 2. 市面类似做法

### 2.1 命令式语音操作

Google Docs 的语音输入支持“输入 + 编辑 + 移动光标 + 停止聆听”等命令，并强调需要显示麦克风、最近识别和命令反馈。这个模式说明：语音控制要可见、可撤销、可确认，不能像隐藏脚本一样默默改变页面。

参考：https://support.google.com/docs/answer/4492226

### 2.2 教育场景的语音练习

Duolingo 的语音能力主要用于语言学习，如跟读、口语练习和 AI 视频对话。它的价值不是“替代点击”，而是把学习行为变成更自然、更低压力的练习入口。

参考：https://blog.duolingo.com/video-call/

Microsoft Reading Coach 让学生朗读并获得实时反馈，体现了教育语音产品的另一个主流方向：用语音采集学习证据，再反馈到学习进度、薄弱项和个性化练习。

参考：https://www.microsoft.com/en-us/education/blog/2024/12/support-independent-ai-powered-reading-practice-with-reading-coach/

### 2.3 技术平台能力

Web Speech API 提供浏览器端语音识别和语音合成能力，适合第一版快速演示。但 MDN 明确标注 `SpeechRecognition` 不是所有主流浏览器都支持；部分浏览器会使用服务端识别，存在离线不可用和隐私提示需求。

参考：https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API
参考：https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition

OpenAI Audio / Realtime 适合第二阶段增强版：文件转写适合有边界的录音请求，Realtime 适合低延迟语音智能体、实时转写和工具调用。若后续要做“边说边问 AI 导师、语音追问诊断、语音生成资料并保存”，应升级到 Realtime + 后端工具调用。

参考：https://platform.openai.com/docs/guides/speech-to-text
参考：https://platform.openai.com/docs/guides/realtime

## 3. CodeTrack 可应用位置

| 页面 | 语音控制价值 | 优先级 |
| --- | --- | --- |
| 题目作答工作区 | 说“第几题选什么、下一题、交卷”，演示效果最直接 | P0 |
| 编程任务工作台 | 说“运行代码、提交判题、获取下一层提示、打开算法演示” | P1 |
| AI 助学 | 语音提问、继续追问、保存为笔记/卡片 | P1 |
| 自主学习 | 说“学习链表、生成 5 道练习、保存笔记” | P1 |
| 我的资料 | 语音搜索资料、打开最近笔记、从资料生成练习 | P2 |
| 学习首页 | 语音快速导航，如“打开机器学习任务” | P2 |

第一版选择“题目作答工作区”，因为它命令边界清晰、状态反馈明显、实现成本低，并且与用户提出的“说第一题选 A、第二题选 B、提交”完全一致。

## 4. 技术路线

### 4.1 轻量演示版

- 前端使用 `SpeechRecognition` / `webkitSpeechRecognition`。
- 识别语言设置为 `zh-CN`。
- 前端命令解析器处理固定意图：选项、填空、跳题、上一题、下一题、保存、交卷。
- 不新增后端接口，直接复用现有保存和提交 API。
- 浏览器不支持时显示降级提示，不影响原有点击作答。

### 4.2 产品增强版

- 把命令解析规则抽成全局 `VoiceCommandBus`。
- 每个页面注册自己的动作表，例如 `select_answer`、`submit_code`、`save_resource`。
- 所有语音动作进入审计日志，记录文本、解析动作、置信度、执行结果。
- 对提交、删除、覆盖等关键动作加入二次确认策略。

### 4.3 AI 语音智能体版

- 使用实时语音转写或语音智能体。
- 后端暴露受控工具：选择答案、提交、生成资料、保存资料、检索课程知识。
- 引入引用守卫代理和权限守卫，避免语音误触发越权或不合规动作。
- 适合演示“语音导师”：学生说“这题为什么我错了”，系统结合题目、画像和课程知识源回答。

## 5. 第一版验收口径

- 页面上有明显的“语音作答控制”面板。
- 支持连续说出多个命令，例如“第一题选 A，第二题选 B”。
- 支持“下一题 / 上一题 / 跳到第三题”。
- 支持“保存草稿 / 交卷”。
- 显示最近识别文本和执行日志。
- 浏览器不支持语音识别时不影响原本作答流程。
