# 学生端智能体工作流登记册

## 1. 文档目的

本文档用于沉淀 CodeTrack 学生端智能体工作流的长期设计。

它只描述产品逻辑、工作流边界、节点职责、页面交互和验收口径，不写具体代码、具体提示词、具体生成内容样例或底层实现细节。

后续如果新增、拆分或调整工作流，优先在本文档中补充，而不是分散写在临时说明里。

本文档承担三件事：

- 记录当前学生端 AI 工作流；
- 固定后端工作流、工具、状态和输出契约的设计方向；
- 为自主学习、资料生成、资料沉淀、练习生成和学习计划扩展提供统一入口。

本文档不是一次性方案。它是后续迭代的工作流总账。

## 2. 当前实现原则

第一版学生端智能体采用：

- 一个学生学习助手；
- 多条固定工作流；
- 一组受控后端工具；
- 统一安全校验；
- 数据库运行记录；
- LangGraph 作为资源生成工作流的编排框架。

核心原则：

- 模型负责理解意图、组织内容和生成结构化草稿；
- 规则负责权限、范围、状态、排序、限制和兜底；
- 工具负责读取课程资料、学生画像、知识库、资料中心和文件生成能力；
- 工作流负责编排步骤、记录中间状态、控制失败重试和返回前端进度；
- 数据库负责保留过程证据、生成结果、引用来源和学生操作；
- 前端只消费结构化结果，不执行模型生成的任意指令；
- 所有可展示给学生的 AI 资源都要暴露来源、置信度、生成状态和下一步动作。

第一版不把学生端 AI 做成自由多智能体自治系统。LangGraph 只用于固定资源生成流程的编排，节点和工具由后端白名单控制。

## 3. 总体大工作流

学生端大闭环分为两条主线和一个贯穿式 AI 助学入口。

### 3.1 教师任务学习闭环

流程：

学习首页 -> 已分配课程任务 -> 任务工作台 -> 代码编辑和提交 -> 沙箱执行 -> 系统验证结果 -> AI 诊断 -> 分层提示 -> 重新提交 -> 学习总结 -> 学习者画像更新 -> 保存学习资料 -> 下一步推荐

首版重点：

- 系统验证结果必须先于 AI 解释展示；
- AI 诊断必须带引用、置信度和下一步动作；
- 提示分为三级，不能直接泄露完整答案；
- 通过后可以生成学习总结，并进入我的资料或资源中心沉淀；
- 工作流记录必须保留模型输出、规则判断和关键步骤状态。

### 3.2 自主学习闭环

流程：

自主学习 -> 选择课程和知识点 -> 查看知识点详情、前置知识、后继知识 -> 选择资源类型 -> 输入学习目标或生成要求 -> 启动资源生成工作流 -> 对话窗口返回资源卡片 -> 学生预览或加入资源中心 -> 资源中心继续管理和导出 -> 学习事件记录 -> 学习者画像更新 -> 下一步推荐

首版重点：

- 知识点从课程知识图谱、课程知识点表或页面上下文读取；
- 内容生成必须绑定课程和知识点；
- 生成资源必须保留引用来源；
- 生成结果在对话窗口中以资源卡片呈现；
- 对话窗口中的资源卡片只提供两个核心交互：加入资源中心、点击卡片实时预览；
- 导出能力只在资源中心提供，不放在对话卡片里；
- 保存的资源必须进入自主学习资源中心，而不是只停留在当前对话页面。

### 3.3 AI 导师贯穿入口

流程：

学生提问 -> 识别页面上下文 -> 识别意图 -> 读取课程、任务、提交、画像和资料上下文 -> 检索课程知识来源或学生知识库 -> 生成结构化回答或资源生成请求 -> 引用校验和答案泄露校验 -> 返回回答、置信度、引用和可执行动作 -> 保存对话和运行记录

AI 导师不是通用聊天框。它必须结合：

- 当前课程；
- 当前页面；
- 当前任务或知识点；
- 学习画像；
- 课程知识库；
- 学生个人知识库；
- 学生有权访问的数据。

## 4. 资源生成交互规范

### 4.1 入口

自主学习页面和 AI 助学页面底部可以展示资源类型按钮，例如：

- PPT；
- 文档；
- 思维导图；
- 练习题；
- 知识卡片；
- 播客脚本。

用户点击某个资源类型后，输入框进入对应的资源生成模式。用户再输入学习目标或生成要求，发送后启动后端资源生成工作流。

### 4.2 对话窗口资源卡片

资源生成完成后，对话窗口不直接展开完整资源内容，而是返回一个资源文件卡片。

资源卡片应表达：

- 资源标题；
- 资源类型；
- 生成状态；
- 资源规模摘要；
- 关联课程和知识点；
- 引用来源数量；
- 置信度；
- 是否已经加入资源中心。

资源卡片在对话窗口中只保留两个核心交互：

- 右侧书签样式按钮：加入资源中心；
- 点击卡片主体：打开实时预览弹窗。

对话窗口不提供导出按钮。导出只在资源中心中提供。

### 4.3 实时预览弹窗

点击资源卡片主体后，页面中央打开资源预览弹窗。

交互要求：

- 弹窗居中展示；
- 弹窗外区域变暗；
- 不跳转页面；
- 不使用右侧抽屉作为主预览方式；
- 弹窗内实时渲染当前资源；
- 弹窗支持关闭后回到原对话；
- 预览内容只展示学生有权访问的资源；
- 资源预览应展示引用来源、AI 生成标识和置信度。

不同资源类型采用统一弹窗外壳，但内部预览方式可以不同：

- PPT 使用逐页幻灯片预览；
- 文档使用正文排版预览；
- 思维导图使用可缩放结构图预览；
- 练习题使用题目、选项和解析预览；
- 知识卡片使用卡片组预览；
- 播客脚本使用脚本文稿预览。

### 4.4 加入资源中心

用户点击书签样式按钮后，系统将该资源加入自主学习资源中心。

加入资源中心后应：

- 更新资源卡片保存状态；
- 写入资源中心记录；
- 写入学习事件；
- 触发学习者画像更新信号；
- 后续在资源中心允许查看、管理和导出。

如果用户没有点击书签，资源仍然可以在当前对话中预览，但不作为正式学习资源沉淀。

### 4.5 资源中心中的导出

导出能力只在自主学习资源中心中提供。

资源中心可根据资源类型提供合适的导出形式：

- PPT 资源可导出为演示文稿文件；
- 文档资源可导出为文档或 PDF；
- 思维导图可导出为图片、文档或结构文件；
- 练习题可导出为练习文档；
- 知识卡片可导出为卡片集；
- 播客脚本可导出为文本稿，后续再扩展音频。

导出属于资源管理能力，不属于对话窗口核心交互。

## 5. LangGraph 接入原则

### 5.1 采用方案 B

当前采用方案 B：提前接入 LangGraph，用于自主学习资源生成工作流。

接入边界：

- 先只覆盖资源生成工作流；
- 不一次性重构已有代码诊断、分层提示和 AI 导师对话；
- 不做开放式自由 agent；
- 每个节点职责固定；
- 每个工具由后端白名单注册；
- 每次运行都写入 AgentRun 和 AgentStep；
- 失败时能定位到具体节点。

### 5.2 LangGraph 在项目中的角色

LangGraph 在 CodeTrack 中不是内容生成器，也不是模型本身。

它承担的是工作流编排角色：

- 按固定顺序执行节点；
- 在节点之间传递共享状态；
- 支持长流程的进度记录；
- 支持失败定位和局部重试；
- 支持后续扩展人工确认、暂停恢复、更多工具节点；
- 支持把确定性步骤和模型步骤放进同一条流程。

资源生成不能只依赖模型直接输出。模型只负责其中一部分节点。完整资源要由多个节点共同完成。

### 5.3 资源生成状态对象

资源生成工作流需要一个共享状态对象，但本文档不规定具体代码结构。

状态中应至少表达：

- 当前运行身份；
- 当前学生；
- 当前课程；
- 当前页面；
- 当前对话；
- 目标资源类型；
- 用户输入；
- 知识点；
- 学习画像摘要；
- 检索到的引用来源；
- 模型生成的资源结构；
- 外部工具或 MCP 生成的渲染结果；
- 文件生成状态；
- 安全校验结果；
- 资源保存状态；
- 错误和重试信息。

### 5.4 节点设计

资源生成工作流建议拆成以下节点：

| 节点 | 作用 |
| --- | --- |
| 创建运行 | 创建一次资源生成运行记录 |
| 权限校验 | 确认学生、课程、知识点和资料访问范围 |
| 上下文构建 | 汇总页面上下文、学习画像、课程信息和对话背景 |
| 意图确认 | 确认用户要生成哪类资源 |
| 知识检索 | 从课程知识库、学生知识库和平台资料中检索可引用依据 |
| 资源规划 | 生成资源结构、章节、页面或内容单元规划 |
| 内容生成 | 生成资源主体内容 |
| 引用校验 | 检查引用是否存在、可访问且与内容相关 |
| 结构校验 | 检查资源是否符合对应类型的结构要求 |
| 外部能力调用 | 调用技能、MCP、文件生成器或渲染器生成可预览资源 |
| 预览构建 | 生成浏览器可实时预览的数据 |
| 文件准备 | 为资源中心中的导出能力准备文件或导出任务 |
| 结果落库 | 保存运行结果和临时资源记录 |
| 返回卡片 | 返回对话窗口可展示的资源卡片信息 |

### 5.5 工具、Skills 和 MCP 的位置

外部能力不直接暴露给前端，也不让模型自由调用。

它们应作为工作流节点中的受控工具出现。

可接入的能力类型包括：

- 课程知识检索工具；
- 学生知识库检索工具；
- 学习画像读取工具；
- 引用校验工具；
- PPT 渲染和文件生成工具；
- 文档渲染工具；
- 思维导图渲染工具；
- 练习题结构校验工具；
- 资源中心保存工具；
- 后续第三方 MCP 或插件工具。

Skills 更适合沉淀“某类产物怎么规范生成”的操作知识。MCP 更适合把外部服务、文件工具、知识库或第三方平台作为可调用能力接进来。LangGraph 负责决定这些能力在流程中的调用顺序和状态传递。

## 6. 工作流清单

### 6.1 工作流 A：编程学习教练

状态：

P0

页面：

- TaskWorkspace

触发方式：

- 学生提交代码；
- 学生查看诊断；
- 学生请求分层提示；
- 学生通过后生成总结。

流程：

学生提交代码 -> 创建提交版本 -> 沙箱执行 -> 保存测试结果 -> 判断通过状态 -> 检索相关知识源 -> 生成诊断或总结 -> 校验引用和答案泄露 -> 写入学习事件 -> 更新任务进度和画像信号

输出：

- 系统执行结果；
- AI 诊断；
- 分层提示；
- 引用来源；
- 置信度；
- 下一步动作。

边界：

- 不替代系统测试结果；
- 不暴露隐藏测试；
- 不直接给完整答案；
- 考核模式下三级提示可关闭。

### 6.2 工作流 B：AI 导师对话

状态：

P0

页面：

- AiTutor；
- TaskWorkspace 右侧 AI 栏；
- SelfStudy 右侧 AI 区；
- LearningLibrary 资源详情；
- LearningProfile 画像详情。

触发方式：

- 学生发送普通问题；
- 学生继续追问；
- 学生从页面动作进入提问。

流程：

校验学生和课程权限 -> 加载页面上下文 -> 识别意图 -> 加载画像、任务、提交或资料摘要 -> 检索课程知识来源 -> 生成回答 -> 校验引用、泄露和动作白名单 -> 保存对话和消息 -> 返回结构化回答

输出：

- 回答；
- 意图；
- 引用来源；
- 置信度；
- 是否使用学习画像；
- 是否使用课程或个人资料；
- 可执行动作。

边界：

- 不做任意工具调用；
- 不访问其他学生数据；
- 不生成虚假引用；
- 不替代正式任务答案。

### 6.3 工作流 C：自主学习资源生成

状态：

P0

页面：

- SelfStudy；
- AiTutor；
- StudentKnowledgeMap。

触发方式：

- 用户点击资源类型按钮；
- 用户输入学习目标或资源生成要求；
- 用户发送后启动资源生成工作流。

资源类型：

- PPT；
- 文档；
- 思维导图；
- 练习题；
- 知识卡片；
- 播客脚本。

流程：

选择资源类型 -> 输入生成要求 -> 校验课程和权限 -> 构建学习上下文 -> 检索知识来源 -> 规划资源结构 -> 生成资源内容 -> 调用必要的渲染或文件能力 -> 校验引用和结构 -> 生成实时预览数据 -> 保存临时资源结果 -> 对话窗口返回资源卡片

输出：

- 资源卡片；
- 实时预览数据；
- 引用来源；
- 置信度；
- 生成状态；
- 加入资源中心所需的保存信息。

对话窗口交互：

- 点击书签按钮加入资源中心；
- 点击资源卡片主体打开实时预览弹窗。

边界：

- 对话窗口不提供导出；
- 导出只在资源中心提供；
- 没有加入资源中心的资源不算正式沉淀资料；
- 资源生成不只依赖模型直出，必须经过检索、校验、渲染或文件准备节点。

### 6.4 工作流 D：资源中心保存与管理

状态：

P0

页面：

- 自主学习资源中心；
- 资源预览弹窗；
- AI 对话资源卡片。

触发方式：

- 用户点击资源卡片右侧书签按钮；
- 用户在资源中心管理已保存资源。

流程：

接收临时资源 -> 校验资源归属和引用来源 -> 写入资源中心 -> 写入学习事件 -> 更新资源保存状态 -> 更新学习者画像信号 -> 在资源中心提供查看、管理和导出

输出：

- 已保存资源；
- 资源详情；
- 资源状态；
- 可导出形式；
- 资源中心列表更新。

边界：

- 只有学生本人可以保存和管理自己的资源；
- 保存前必须确认资源类型合法；
- 保存前必须确认引用来源合法；
- 导出从资源中心触发，不从对话窗口触发。

### 6.5 工作流 E：个性化练习生成

状态：

P1

页面：

- SelfStudy；
- AiTutor；
- LearningProfile。

触发方式：

- 用户选择生成练习题；
- 系统根据薄弱知识点推荐练习。

流程：

选择知识点 -> 读取掌握度和错因 -> 确定难度 -> 检索课程知识 -> 生成题目结构 -> 校验题目、选项和解析 -> 生成练习资源卡片 -> 用户预览或加入资源中心 -> 学生作答后更新学习事件

第一版题型：

- 单选题；
- 多选题；
- 判断题。

边界：

- 暂不生成正式考试题；
- 暂不生成新的编程判题题目；
- 不把练习结果等同于正式课程成绩。

### 6.6 工作流 F：学习计划与下一步推荐

状态：

P1

页面：

- LearningHome；
- LearningProfile；
- AiTutor；
- TaskWorkspace 完成总结。

触发方式：

- 学生打开首页；
- 学生完成任务；
- 学生保存资源；
- 学生查看画像。

流程：

读取未完成任务、截止时间、画像和错因 -> 规则生成候选动作 -> 排序 -> AI 组织成学生可理解的解释 -> 保存计划版本 -> 前端展示可执行动作

推荐动作类型：

- 完成任务；
- 重做任务；
- 复习知识点；
- 生成练习；
- 阅读资源；
- 打开自主学习；
- 查看教师反馈。

## 7. 意图枚举

第一版只允许固定意图，不让模型自由创造意图名称。

基础意图包括：

- 概念解释；
- 代码解释；
- 任务指导；
- 练习生成；
- 笔记生成；
- 知识卡片生成；
- 思维导图生成；
- PPT 生成；
- 文档生成；
- 播客脚本生成；
- 学习计划；
- 资源推荐；
- 通用追问。

无法确定时使用通用追问。

## 8. 页面上下文枚举

页面上下文用于限制工作流读取哪些业务数据。

第一版页面上下文包括：

- 学习首页；
- 课程任务；
- 任务工作台；
- 客观题工作台；
- 自主学习；
- AI 助学；
- 资源中心；
- 学习者画像；
- 课程知识图谱。

不同页面只加载必要上下文。

例如：

- 任务工作台加载任务、提交、测试结果、诊断和提示摘要；
- 自主学习加载当前知识点、画像摘要和课程知识源；
- 资源中心加载当前资源、引用和相关知识点；
- 学习者画像加载薄弱知识点、高频错因和推荐。

## 9. 动作白名单

AI 只能返回固定动作类型，前端只执行这些白名单动作。

允许动作包括：

- 打开任务；
- 打开学习者画像；
- 打开自主学习；
- 打开资源中心资源；
- 生成练习；
- 生成笔记；
- 生成知识卡片；
- 生成思维导图；
- 生成 PPT；
- 生成文档；
- 生成播客脚本；
- 加入资源中心；
- 更新学习计划；
- 继续追问；
- 打开资源预览弹窗。

不得返回：

- 任意数据库操作；
- 任意后端函数名；
- 任意脚本；
- 任意外部跳转；
- 修改成绩动作；
- 修改教师任务动作；
- 访问其他学生数据的动作。

## 10. 安全校验

所有学生端 AI 输出都必须经过：

权限校验 -> 上下文范围校验 -> 结构校验 -> 引用校验 -> 答案泄露校验 -> 内容长度校验 -> 动作白名单校验

### 10.1 引用校验

模型返回的引用必须满足：

- 来源存在；
- 属于当前课程、当前学生知识库或平台允许访问范围；
- 当前学生可访问；
- 来源状态有效；
- 与当前问题、知识点或资源内容相关。

### 10.2 答案泄露校验

检查范围：

- 完整函数实现；
- 明确参考答案；
- 隐藏测试输入输出；
- 可直接复制提交的完整代码；
- 超过当前提示等级的内容。

### 10.3 低置信度处理

如果引用不足、模型失败、外部工具失败或上下文不足，应：

- 降低置信度；
- 标记风险；
- 使用规则模板兜底；
- 明确提示学生当前回答依据不足；
- 给出可执行下一步，而不是空白失败。

## 11. 运行记录

建议继续使用并扩展现有运行记录。

运行记录应表达：

- 一次工作流运行；
- 运行所属学生、课程和页面；
- 工作流类型；
- 输入摘要；
- 输出摘要；
- 使用的模型、工具或外部能力；
- 每个节点的开始、结束和状态；
- 失败节点和失败原因；
- 生成资源与对话消息、资源中心记录之间的关联。

资源生成工作流尤其需要记录：

- 用户选择的资源类型；
- 命中的知识点；
- 使用的引用来源；
- 是否调用外部工具或 MCP；
- 是否生成可预览资源；
- 是否准备导出文件；
- 是否加入资源中心。

## 12. LangChain 与 LangGraph 的关系

LangChain 和 LangGraph 都能参与“让模型完成任务”，但它们处在不同层级。

LangChain 更像模型应用框架：

- 组织模型、提示词、工具和中间件；
- 适合做模型调用、工具调用和普通 agent loop；
- 更关注一次任务中模型如何思考、如何选择工具、如何返回结果。

LangGraph 更像工作流编排和运行时：

- 把任务拆成节点；
- 节点之间共享状态；
- 支持确定性步骤和模型步骤混合；
- 支持长流程、暂停、恢复、流式进度、人工确认和失败重试；
- 更适合 CodeTrack 这种需要可控流程、可观测步骤和多工具协作的资源生成链路。

在 CodeTrack 中推荐：

- 用 LangGraph 编排资源生成工作流；
- 在需要模型调用或工具调用的节点里使用 LangChain 相关能力；
- 不让 LangChain agent 自由决定所有流程；
- 不让模型绕过后端权限、引用和资源保存规则。

简化理解：

- LangChain 解决“模型和工具怎么配合”；
- LangGraph 解决“整个任务流程怎么被拆分、推进、记录和恢复”。

## 13. 当前 PPT 生成工作流设想

PPT 只是资源生成的一种类型，但它最能体现“模型 + 检索 + 渲染 + 文件准备 + 资源中心”的完整流程。

当前 PPT 生成建议流程：

用户点击 PPT 按钮 -> 输入生成要求 -> 启动资源生成工作流 -> 校验课程和学生权限 -> 识别知识点 -> 检索课程资料和学生知识库 -> 读取学习画像摘要 -> 规划幻灯片结构 -> 生成每页内容 -> 校验引用和结构 -> 调用 PPT 渲染能力生成浏览器预览 -> 准备资源中心可导出文件 -> 返回对话资源卡片

关键原则：

- PPT 不是只生成大纲；
- 对话中展示的是资源卡片；
- 点击卡片可以实时预览完整 PPT；
- 点击书签可以加入资源中心；
- 导出只在资源中心提供；
- 模型只负责内容和结构，不负责所有文件能力；
- 文件生成、预览渲染、引用校验和保存都应由工作流节点完成。

## 14. 当前思维导图生成工作流设想

思维导图是自主学习资源生成中的结构化理解型产物。它不应只把模型回答拆成几个缩进标题，而应帮助学生看清一个知识点的核心概念、前置基础、关键关系、易错点、例题联系和下一步学习动作。

思维导图生成推荐采用“工作流控制流程 + 智能体负责结构规划和质量修订”的方式。

### 14.1 适用场景

首版重点用于人工智能专业三门演示课程中的知识点梳理：

- 机器学习：监督学习、损失函数、过拟合、梯度下降等概念关系；
- Python 程序设计：函数、列表、字典、异常处理、文件读写等编程基础；
- 数据结构：链表、栈与队列、二叉树、递归遍历等结构和算法关系。

思维导图主要解决：

- 学生不知道一个知识点应该从哪里学起；
- 学生只记住定义，但看不清概念之间的关系；
- 学生完成任务后需要把错因、知识点和修正方法沉淀成结构化资料；
- 学生希望把 AI 问答或自学内容保存成可复习的资源。

### 14.2 触发入口

触发入口复用资源生成入口：

```text
自主学习页 / AI 导师 / 任务工作台总结区
-> 点击“思维导图”
-> 输入学习目标或生成要求
-> 启动自主学习资源生成工作流
-> 返回思维导图资源卡片
```

典型输入示例：

```text
帮我把链表删除节点整理成适合复习的思维导图
```

```text
围绕机器学习里的过拟合，生成一张包含原因、表现、解决方法和例题联系的思维导图
```

### 14.3 工作流链路

推荐链路：

```text
创建运行
-> 权限校验
-> 页面和课程上下文构建
-> 知识点识别
-> 检索课程资料和学生知识库
-> 读取学习画像摘要
-> Mind Map Planner Agent 规划导图结构
-> Mind Map Content Agent 生成节点内容
-> Relationship Refiner Agent 补全节点关系
-> Citation Guard Agent 校验引用
-> Mind Map Critic Agent 质量评审
-> 必要时局部重写
-> 结构校验
-> 预览数据构建
-> 临时资源落库
-> 返回对话资源卡片
```

其中工作流负责顺序、状态、权限、重试和落库；智能体只在规划、生成、关系整理、质量评审这些节点中工作。

### 14.4 Agent 节点职责

Mind Map Planner Agent 负责把用户目标转成导图骨架。

输入：

```text
user_request
course
knowledge_points
retrieved_sources
learner_profile_summary
page_context
```

输出：

```text
central_topic
map_purpose
target_depth
top_level_branches
required_relationship_types
coverage_requirements
```

Mind Map Content Agent 负责为每个节点生成短文本内容。

输出要求：

```text
node_id
parent_id
title
summary
node_type
knowledge_points
citations
confidence
```

Relationship Refiner Agent 负责补全节点之间的语义关系，避免导图只是目录树。

关系类型首版固定为：

```text
prerequisite
contains
causes
solves
example_of
common_mistake
next_step
contrast
```

Mind Map Critic Agent 负责质量检查和局部修订建议。

检查重点：

- 中心主题是否明确；
- 分支是否覆盖用户要求；
- 层级是否过深或过浅；
- 是否存在空泛节点；
- 是否包含与学生画像相关的薄弱点提醒；
- 是否有引用不足或引用不相关节点；
- 是否存在明显概念错误；
- 是否适合移动端和桌面端预览。

### 14.5 输出结构

思维导图工作流输出必须是结构化数据，而不是一段 Markdown。

建议结构：

```json
{
  "artifact_type": "MIND_MAP",
  "title": "链表删除节点复习思维导图",
  "central_topic": "链表删除节点",
  "course_id": "data_structure",
  "knowledge_points": ["链表", "指针更新", "边界条件"],
  "nodes": [
    {
      "node_id": "root",
      "parent_id": null,
      "title": "链表删除节点",
      "summary": "理解删除节点时指针如何重新连接，以及头节点和空链表等边界情况。",
      "node_type": "central_topic",
      "depth": 0,
      "citations": ["src_linked_list_01"],
      "confidence": 0.88
    }
  ],
  "edges": [
    {
      "source_node_id": "boundary_cases",
      "target_node_id": "delete_head",
      "relationship_type": "contains",
      "label": "包含"
    }
  ],
  "citations": [],
  "confidence": 0.86,
  "risk_flags": [],
  "recommended_next_actions": ["生成练习", "保存到资源中心", "继续追问"]
}
```

节点类型首版固定为：

```text
central_topic
concept
procedure
example
mistake
profile_tip
practice
next_action
```

### 14.6 预览与前端交互

对话窗口只返回资源卡片，不直接展开完整导图。

资源卡片展示：

- 标题；
- 类型：思维导图；
- 关联课程和知识点；
- 节点数量；
- 引用来源数量；
- 置信度；
- 生成状态；
- 是否已加入资源中心。

点击卡片主体后打开居中预览弹窗。

预览弹窗要求：

- 中心主题在视觉中心；
- 一级分支清晰可扫读；
- 支持缩放、拖拽和平移；
- 支持节点展开和收起；
- 节点点击后展示摘要、引用来源和下一步动作；
- 低置信度或引用不足节点要有可见标识；
- 移动端默认展示一层分支，允许逐层展开；
- 不在对话卡片里提供导出按钮。

资源中心中的导出可以支持：

- PNG 图片；
- Markdown 大纲；
- JSON 结构文件；
- 后续扩展为 XMind、FreeMind 或 PDF。

### 14.7 质量标准

一张可用的思维导图必须满足：

- 中心主题只表达一个明确知识点或任务主题；
- 一级分支数量建议 4-7 个；
- 总节点数量首版建议 12-35 个；
- 单个节点标题不超过 18 个中文字符；
- 节点摘要不超过 80 个中文字符；
- 至少包含一个“易错点”或“画像提醒”分支；
- 涉及课程知识的概念节点必须有引用；
- 不能把完整作业答案作为节点内容；
- 不生成虚构教材、论文或来源；
- 低置信度节点必须标注风险，并给出继续学习动作。

### 14.8 失败兜底

如果检索来源不足：

```text
降低置信度
-> 使用课程知识点和规则模板生成轻量导图
-> 标记“引用不足”
-> 推荐学生上传资料或切换知识点
```

如果结构校验失败：

```text
返回 Mind Map Critic Agent
-> 局部重写节点
-> 再次校验
-> 仍失败则返回简化导图
```

如果渲染失败：

```text
保留结构化 JSON 和 Markdown 大纲
-> 资源卡片标记预览生成失败
-> 允许稍后在资源中心重新生成预览
```

### 14.9 验收标准

第一版思维导图生成必须能演示：

```text
学生在自主学习页选择“链表”
-> 点击“思维导图”
-> 输入复习目标
-> 后端创建资源生成运行记录
-> 工作流检索课程资料和画像摘要
-> 返回思维导图资源卡片
-> 点击卡片打开居中预览弹窗
-> 节点可展开、可查看引用和置信度
-> 点击书签加入资源中心
-> 资源中心可再次打开预览
```

同时满足：

- 运行记录能看到每个节点状态；
- 生成结果能关联课程、知识点和学生；
- 引用来源来自课程资料、学生知识库或平台资料；
- 资源卡片和预览弹窗复用通用资源生成交互；
- 失败时有可见状态、风险说明和下一步动作。

## 15. 开发顺序

### 15.1 第一阶段：资源生成工作流骨架

- 接入 LangGraph；
- 定义资源生成工作流状态；
- 定义固定节点；
- 接入 AgentRun 和 AgentStep；

- 对话窗口支持资源卡片；
