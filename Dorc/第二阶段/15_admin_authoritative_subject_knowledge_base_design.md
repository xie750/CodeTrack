# 管理员端权威学科知识库设计

## 1. 判断结论

在管理员端构建平台内置的权威学科知识库是合理的，而且应当作为第二阶段垂类助学能力的关键支撑。

原因是：垂类模型不能只依赖微调模型本身。微调可以让模型熟悉人工智能专业的表达、任务类型和诊断风格，但无法保证每一次回答都引用真实、可追溯、经过审定的课程知识。面向学生的 AI 诊断、概念讲解和资料生成，需要一个可检索、可引用、可审计的权威知识底座。

## 2. 需要反驳或修正的点

不建议把所有知识库都做成同一种“用户自定义知识库”。

如果学生端、教师端和平台端资料都混在一个概念里，会产生三个问题：

- 质量边界不清：学生上传资料、教师课件和平台审定教材片段的可信度不同。
- 引用责任不清：AI 回答引用了谁的材料、是否经过审定，前端难以解释。
- 运维治理不清：管理员无法看见学科覆盖、待审核来源、低质量来源和引用风险。

因此应该做成分层知识源，而不是一个大而全的知识库入口。

## 3. 推荐分层

```text
平台权威学科知识库
-> 管理员端维护
-> 来源需登记、审核、发布
-> AI 默认优先检索

教师课程资料库
-> 教师端维护
-> 服务具体课程、班级和任务
-> AI 在课程上下文中补充检索

学生个人知识库
-> 学生端自建
-> 服务个人复习、自主学习和资料沉淀
-> AI 只作为个人上下文补充
```

学生端 AI 引用展示时应区分：

```text
平台权威来源 / 教师资料 / 我的知识库
```

## 4. 管理员端页面定位

管理员端页面不直接面向学生，也不做成普通文件管理器。

页面目标是让管理员回答四个问题：

- 当前人工智能专业三门首版课程是否有权威知识覆盖。
- 每门课程的权威来源是否经过审定。
- 可引用片段数量、覆盖率和引用通过率是否达标。
- 哪些来源需要复核，是否可以发布给学生端 AI 使用。

## 5. 首版管理对象

### 5.1 AuthoritativeKnowledgeBase

```text
id
subject
course_name
version
status
owner
coverage_rate
source_count
chunk_count
citation_pass_rate
retrieval_priority
publish_scope
quality_gates
retrieval_policy
last_updated_at
```

### 5.2 AuthoritativeKnowledgeSource

```text
id
knowledge_base_id
title
kind
publisher
chapter
status
reviewer
chunk_count
quality_score
updated_at
```

来源类型首版包括：

- 课程标准；
- 教材；
- 教师审定讲义；
- 公开规范；
- 题库解析。

## 6. AI 检索策略

学生端和教师端 AI 工作流检索时，建议使用以下优先级：

```text
1. 平台已发布权威学科知识库
2. 教师端已发布课程资料
3. 学生个人知识库
4. 通用模型自身知识
```

当平台权威库命中不足时，才补充教师资料或学生资料。通用模型自身知识不能伪装成课程来源。

## 7. 质量门槛

权威库发布前至少满足：

- 来源身份已登记；
- 章节或知识点已映射；
- 切片可以回溯到来源；
- 引用片段可在前端展示；
- 待审核来源不能进入发布版本；
- 低置信回答必须触发复核或提示学生核查。

## 8. 首版开发范围

本次先落地管理员端原型级垂直切片：

- 新增管理员端“权威知识库”导航；
- 展示三门首版课程的权威库覆盖；
- 展示来源审核状态、质量分和切片数量；
- 支持新增权威来源进入待审核；
- 支持将来源标记为审定；
- 支持在全部来源审定后发布课程知识库；
- 展示检索优先级和引用治理策略。

真实文件解析、embedding、混合检索和权限审计可以继续复用或扩展现有 RAG 服务。

## 9. 后续工程接入

后续后端可新增或复用 RAG 表，将平台权威知识源作为单独 source kind：

```text
PLATFORM_AUTHORITATIVE
TEACHER_RESOURCE
STUDENT_KNOWLEDGE_BASE
```

AI 响应 citation 建议统一输出：

```json
{
  "source_kind": "PLATFORM_AUTHORITATIVE",
  "knowledge_base_id": "AKB-DS-001",
  "source_id": "DSS-1",
  "chunk_id": "chunk_dss_001_0001",
  "title": "单链表边界处理讲义",
  "section_title": "线性表",
  "trust_level": "AUTHORITATIVE"
}
```

这样可以让学生端看到“引用来自平台权威来源”，同时保留教师端和学生端自定义知识库的灵活性。
